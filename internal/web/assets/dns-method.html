The DNS check.

How a domain itself is served: its name servers, its records and its DNSSEC chain.

What is read

Through the resolver: A, AAAA, CNAME, NS and their addresses, SOA, TXT, DS and DNSKEY.

Directly, over TCP port 53, for a domain this installation has been shown control of:

  • whether each name server answers for the zone;
  • whether each allows a zone transfer. The transfer is closed before any record is read;
  • whether a name server inside the domain answers for other domains;
  • which name servers the parent zone hands out.

Private, loopback and reserved addresses are refused. Subdomains are never guessed.

What is graded

Only what stops a resolver:

  • fewer than two name servers, or all on one network (RFC 1034, RFC 2182);
  • a name server that resolves to nothing (RFC 1912);
  • a parent that hands out different name servers, or glue the zone does not publish (RFC 1912);
  • a DNSSEC chain that does not check out, or an expired signature (RFC 4035);
  • an alias at the top of a zone (RFC 1034, RFC 2181).

Reported, not graded: the records, serial and timers, the signing algorithm, whether servers hold the same serial, whether the zone can be transferred (RFC 5936 does not call it a fault), and whether absent names are proved with hashed names.

The DNSSEC chain

If the digest at the parent does not match a key the zone publishes, validating resolvers return nothing and the domain disappears for most of the internet. This check computes each key’s digest (RFC 4034) and compares it with the parent’s. It does not verify every signature; where the resolver says it did, the report says so.

An alias whose target is gone

If the name is an alias and its target no longer exists, whoever claims that target next can answer for your name and get a certificate for it. This is reported, not graded.
