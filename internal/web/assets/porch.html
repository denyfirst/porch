Run it yourself

Three steps.

You need a Linux server with Docker.

  1. Get it

    Downloads the compose file shown below and checks its signature. The last line must print Good "file" signature with the key SHA256:ut6bginhZ4lZINMSXNDv3vJ6fyvmDHhtnoBJH0/Nr9Y and docker-compose.yml: OK. If not, the file is removed. More on verifying.

    on the server 
    mkdir -p porch && cd porch
for f in docker-compose.yml SHA256SUMS SHA256SUMS.sig; do curl -fsSLO "https://github.com/denyfirst/porch/releases/latest/download/${f}"; done
echo 'releases@denyfirst.dev ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAIDD7Ie9zRf76RynH052/Abkv5k2nzosQd2DihyQMixVR' > allowed_signers
ssh-keygen -Y verify -f allowed_signers -I releases@denyfirst.dev -n file -s SHA256SUMS.sig < SHA256SUMS && sha256sum --ignore-missing -c SHA256SUMS || { rm -f docker-compose.yml; echo 'STOP: docker-compose.yml did not verify and was removed'; }

  2. Start it

    Create the data folder and start Porch. The first start prints a password in docker compose logs.

    on the server 
    mkdir -p porch-data && sudo chown 65534:65534 porch-data
docker compose up -d

  3. Open it

    Porch listens only on the server. Connect through SSH, then open http://localhost:8080.

    on your computer 
    ssh -L 8080:127.0.0.1:8080 you@your-server

What you are about to run: docker-compose.yml

Read it before you run it. Step 1 downloads and checks the real file.

docker-compose.yml 
services:
  porch:
    image: ghcr.io/denyfirst/porch@{{.ImageDigest}}
    command:
      - "-listen"
      - "0.0.0.0:8080"
      - "-verification-secret-file"
      - "/data/secret"
      - "-access-file"
      - "/data/access"
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - /etc/ssl/certs:/etc/ssl/certs:ro
      - ./porch-data:/data
    environment:
      SSL_CERT_DIR: /etc/ssl/certs
    read_only: true
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
    restart: unless-stopped
  scan:
    image: ghcr.io/denyfirst/porch@{{.ImageDigest}}
    profiles: ["cli"]
    entrypoint: ["/porch-scan", "-verification-secret-file", "/data/secret"]
    volumes:
      - /etc/ssl/certs:/etc/ssl/certs:ro
      - ./porch-data:/data:ro
    environment:
      SSL_CERT_DIR: /etc/ssl/certs
    read_only: true
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL

Why self-hosted

Porch, or an online scanner?

The same kind of checks. The difference is where the result ends up.

Porch

  1. You
  2. Your server
  3. Your domain

The result stays on your server, encrypted under your password.

An online scanner

  1. You
  2. Their server
  3. Your domain

Their server sees the domain and keeps the result.

PorchYours

Questions

Before you ask.

Six short answers. Each card names the document that says it at length.

Does Porch send my results anywhere?

No.

Results are kept only where you say, on your own machine. No account with us, no telemetry.

Source self-host.md

Can it check any domain?

Only yours.

You prove a domain with a TXT record or a file on the site, and the proof is read again on every scan.

Source scope.md

What will the checked server see?

A polite visit.

Handshakes and ordinary requests. No guessed paths, no exploits, no logins, and every web request names Porch.

Source checks.md

What do I need to run it?

Docker.

A Linux server with Docker. No Go, no source, no build. The command line also runs on macOS and Windows.

Source README.md

How do I know the download is yours?

Signed.

Every release is signed and rebuilds byte for byte. Step 1 above checks the signature with this key:

SHA256:ut6bginhZ4lZINMSXNDv3vJ6fyvmDHhtnoBJH0/Nr9Y

Source verify.md

Is it free?

Yes.

Open source under AGPL-3.0. No paid tier, no investors, nothing to sign up for.

Source LICENSE
