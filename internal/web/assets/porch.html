How it works

From connection
to clarity.

Here it checks our own domain. Run it yourself for the infrastructure you are responsible for.

01 / Connect

Ask what a client asks.

Handshakes at each TLS version, one request for the front page, and the DNS records a mail server reads. Nothing is sent that a browser or a mail server would not send.

02 / Examine

Grade against a named rule set.

Each check has its own rule set, and every finding cites the standard it rests on. Where no standard sets a line, the fact is reported rather than graded.

03 / Understand

Start with what matters.

Each check leads with its verdict and its findings, with the tables and limits underneath. Your own copy lets you save every report.

Get started

Your own copy,
in three steps.

Docker on the server, and beside it only what the release signed: the service, its command line and the three files that run them. No source goes there.

  1. Get it

    On the server, the latest release for its processor: the service, its command line, the three files that run them, and the signed list of their hashes. Then check them all as docs/verify.md says, before anything runs. Nothing is built there, so the server needs Docker and nothing else — no Go, no source.

    on the server 
    mkdir -p porch && cd porch
V=$(basename "$(curl -fsSLo /dev/null -w '%{url_effective}' https://github.com/denyfirst/porch/releases/latest)")
A=$(uname -m | sed 's/x86_64/amd64/; s/aarch64/arm64/')
for f in "porchd_${V}_linux_${A}" "porch-scan_${V}_linux_${A}" Dockerfile Dockerfile.dockerignore docker-compose.yml SHA256SUMS SHA256SUMS.sig; do curl -fsSLO "https://github.com/denyfirst/porch/releases/download/${V}/${f}"; done

  2. Start it

    Once the signature and every hash check out: name the binaries, give the container a data directory, and start it. Proof of control and a password are on from the first start, and nothing turns them off.

    on the server 
    mv porchd_*_linux_* porchd && mv porch-scan_*_linux_* porch-scan
mkdir -p porch-data && sudo chown 65534:65534 porch-data
docker compose up -d --build

  3. Open it

    It listens only on the server itself. Reach it through SSH, then open http://localhost:8080.

    on your computer 
    ssh -L 8080:127.0.0.1:8080 you@your-server

What you are about to run: docker-compose.yml

Already in what step 1 downloaded and covered by its signature, so it is shown here to be read rather than copied: no image pulled from a registry, the port published on the server's own loopback, nothing in the container writable but its data directory, and every capability dropped. The comments in the file say why each line is there.

docker-compose.yml 
services:
  porch:
    build: .
    image: porch
    pull_policy: build
    command:
      - "-listen"
      - "0.0.0.0:8080"
      - "-verification-secret-file"
      - "/data/secret"
      - "-access-file"
      - "/data/access"
    ports:
      - "127.0.0.1:8080:8080"
    volumes:
      - /etc/ssl/certs:/etc/ssl/certs:ro
      - ./porch-data:/data
    environment:
      SSL_CERT_DIR: /etc/ssl/certs
    read_only: true
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
    restart: unless-stopped
  scan:
    image: porch
    pull_policy: never
    profiles: ["cli"]
    entrypoint: ["/porch-scan", "-verification-secret-file", "/data/secret"]
    volumes:
      - /etc/ssl/certs:/etc/ssl/certs:ro
      - ./porch-data:/data:ro
    environment:
      SSL_CERT_DIR: /etc/ssl/certs
    read_only: true
    security_opt:
      - no-new-privileges:true
    cap_drop:
      - ALL
